# TrendPilot Server

سرور بکند TrendPilot — طبق بخش ۴ سند مشخصات. تمام منطق معاملاتی
(اندیکاتور، سیگنال روند/اسکلپ، تشخیص رژیم بازار، مدیریت ریسک،
مدیریت پوزیشن، بکتست، موتور AI کمکی) اینجا پیاده‌سازی شده — هیچ
منطقی در سمت MT5/ویندوز نیست.

## ساختار

```
server/
  src/
    indicators/engine.ts        # موتور اندیکاتور خالص (بخش ۴.۱)
    signals/trend.ts            # موتور سیگنال روند (بخش ۴.۲)
    signals/scalp.ts            # موتور سیگنال اسکلپ (بخش ۴.۳)
    signals/regime.ts           # تشخیص رژیم بازار (بخش ۴.۴)
    risk/risk.ts                # مدیریت ریسک (بخش ۴.۵)
    risk/position-management.ts # مدیریت پوزیشن باز (بخش ۴.۶)
    engine/decision.ts          # هسته‌ی تصمیم مشترک بین زنده و بکتست (بخش ۴.۸)
    live/bot-manager.ts         # اجرای زنده + چند-پروفایلی (بخش ۴.۷)
    backtest/                   # موتور بکتست + Job async (بخش ۴.۸)
    ai/                         # موتور AI کمکی — استخراج ویژگی + رگرسیون لجستیک (بخش ۴.۹)
    store/                      # ذخیره‌سازی JSON پایدار پروفایل‌ها/گروه نماد (بخش ۴.۱۰)
    api/routes.ts               # همه‌ی endpointهای بخش ۷ + endpoint داخلی analyze (بخش ۴.۱۲)
    index.ts                    # نقطه‌ی ورود Fastify
  data/                         # فایل‌های JSON پایدار (به‌صورت خودکار ساخته می‌شود)
```

## اجرا

```bash
cd server
npm install
npm run dev      # اجرای توسعه با ری‌لود خودکار (tsx watch)
# یا برای پروداکشن:
npm run build
npm start
```

سرور پیش‌فرض روی پورت `8787` بالا می‌آید (قابل تغییر با متغیر محیطی `PORT`).

## تست‌ها

```bash
npx tsx src/tests/indicators.test.ts   # موتور اندیکاتور
npx tsx src/tests/decision.test.ts     # هسته‌ی تصمیم مشترک
npx tsx src/tests/backtest.test.ts     # موتور بکتست
npx tsx src/tests/ai.test.ts           # موتور AI کمکی
```

## اتصال فرانت‌اند

در پروژه‌ی فرانت‌اند (ریشه‌ی ریپو)، متغیر محیطی زیر را ست کنید تا
به‌جای داده‌ی mock از این سرور واقعی استفاده شود:

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:8787
```

## نکات طراحی مهم / انحراف‌های کوچک از سند اصلی (شفاف‌سازی)

سند اصلی (PDF) دو نقطه را کامل مشخص نکرده بود؛ برای این‌که سیستم واقعاً
کار کند، این تکمیل‌ها به‌صورت حداقلی اضافه شدند:

1. **`profile_name` در بدنه‌ی `POST /api/v1/analyze`**: سند بدنه را فقط
   `{ symbol, timeframeMinutes, candles }` تعریف کرده بود، اما چون هر
   پروفایل تنظیمات/Magic Number مستقل خودش را دارد (بخش ۴.۷)، بدون
   دانستن این‌که پل EA برای کدام پروفایل کندل می‌فرستد، مسیریابی به
   تنظیمات درست ممکن نیست. فیلد `profile_name` اضافه شد.

2. **منبع داده‌ی تاریخی بکتست**: سند فقط جریان داده‌ی *زنده* (کندل از
   MT5) را مشخص کرده؛ منبع داده‌ی *تاریخی* برای بکتست مشخص نشده بود.
   فعلاً یک تولیدکننده‌ی داده‌ی مصنوعیِ قطعی در `backtest/data-provider.ts`
   استفاده می‌شود تا موتور بکتست کاملاً قابل تست/نمایش باشد. جایگزینی
   آن با یک منبع واقعی (تاریخچه‌ی بروکر، یا API یک ارائه‌دهنده‌ی داده)
   فقط نیازمند پیاده‌سازی مجدد `HistoricalDataProvider` است — هیچ
   بخش دیگری از سرور تغییر نمی‌کند.

3. **دفتر معاملات (Position Ledger)**: چون طبق طراحی سند، EA سمت MT5
   هیچ تأییدیه‌ی fill/P&L واقعی به سرور برنمی‌گرداند (فقط کندل می‌فرستد
   و دستور را اجرا می‌کند)، سرور یک دفتر معاملات کاغذی (paper ledger)
   نگه می‌دارد تا داشبورد/پوزیشن‌ها/گزارش معنا داشته باشند. اگر بعداً
   بخواهید MT5 واقعاً fill/قیمت واقعی را هم گزارش کند، کافی‌ست
   `live/bot-manager.ts` را با آن داده‌ی واقعی به‌روزرسانی کنید.
